# 独立全屏场景，而非读数页底部常驻趋势条

读数、趋势、统计各为独立全屏场景，由显示板本地键（如 DISPLAY）切换；里程碑-1 只实现读数场景，但场景框架按多场景建模（`scene_enter/exit/render`），切换逻辑待趋势里程碑接入。

## Status

accepted

## Considered Options

- **独立全屏场景（选定）**：横屏 960×320 高度仅 320px，常驻趋势条会严重挤压大读数；每个场景拿到完整画面，布局清爽。
- **读数页底部常驻趋势条**（原 `2026-08-09-dmm-ui-design.md` 方案）：趋势随时可见，但挤占读数区，且趋势/统计状态与读数场景耦合。
- **混合**：读数页常驻底部趋势条 + 独立全屏统计页：复杂度高于收益，两处趋势渲染路径重复。

## Consequences

- 场景切换由显示板本地键触发；DISPLAY/TREND 键在里程碑-1 仍透传主机，不解释。
- 趋势采样缓冲（trend_buf）是纯数据层，不随场景销毁；场景切换只换渲染入口。
- 里程碑-1 验收只覆盖读数场景，但 `scene_enter/exit/render` 接口现在就存在，避免事后重构。
