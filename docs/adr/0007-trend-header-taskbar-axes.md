# ADR-0007: 趋势区 header / 任务栏 / 纵轴

- 状态：已接受（2026-09-03）
- 前置：ADR-0006（底部只留绘图区）被本决策部分取代——绘图区让出 header / 任务栏 / Y 沟槽。

## 布局（底部 y192..319）

- header（y192 h26，BAR 底）：左侧 `Trend` 白字；右侧依次 `MAX v` / `AVG v` / `MIN v`（白）＋档位范围（绿， far right）。
- 绘图区（x96..960，y218..296，黑底）：5 条纵指示线（GRID），无横线、无标签悬浮。
- 任务栏（y296 h24，BAR 底）：纵线下方流逝时间（`10s 7.5s 5s 2.5s 0s`，青色），`0s` 在最新数据点（最右）。
- 左沟槽（x0..96，BAR 底）：resident 轴的最大/中/最小标签（青色右对齐）。

## 数据来源

- 档位范围由 resident 轴推导（`s_trend_axis_min/max/unit`），如 `±10V` / `100kΩ`（k/M 进制、DC/AC 后缀剥离、手动两位小数，无 float printf）；无数据时 `--`。
- MAX/AVG/MIN 沿用 `main_display_format_trend()` 的窗口统计文本；无数据时 `--`。
- 纵轴标签沿用 `main_display_format_linear_trend_labels()`（投影后的 resident 跨度）。
- 流逝时间由 `TREND_WINDOW_MS`（10s）五等分推导，与 sweep 槽位同源，刷新（背景重建）后重画。

## 渲染约束

- header 右块每串独占一步（单任务规则）；右对齐累计只在串之间垫间隔。
- 槽位擦除回补被盖住的纵指示线段（`trend_sweep_restore_verticals`）；回卷清屏后重画 5 线。
- Y 标签只在背景重建时绘制（同单位漂移不触发重建，标签即 resident 身份，天然稳定）。
- 空窗显示居中 `WAITING FOR DATA`；首个样本（单位变化）触发背景重建。

## 后续调整：Trend 徽标＋绘图顶端绿线

- `Trend` 改为仿档位徽标（绿底黑字，80px 宽 Badge，与行2档位标签同语言），不再是 header 上的白字。
- 绘图区顶端加全幅 2px 绿线（与行2分隔线同高同色）；纵指示线、顶部 Y 标签、擦除回补、回卷重画一律从线下起算，互不覆盖。

## live 去阻塞 present（2026-09-04）

- 症状：统计刷新时读数冻住、刷新完恢复——live 整 pass 跑完才放行提交。
- 修复：live 每帧最多一片，画完即提交、下一帧续跑；双页＋逐槽快照发布保证任何切割点两页恒等。预算 4→2。
- 实测：稳态 fps 30、帧 ~10ms；轮换一窗恢复。`missed=0`、无 error。

## 实时跟随回归（2026-09-04，慢闪安全版）

- 快照保稳定、刷新保实时：槽位值仍首建抓取（兄弟页恒等、不闪），另加 1Hz live 刷新——只差分变化字形（擦除精确到 12px 变化格），静态 BAR/徽标/Trend 永不重画。
- 字形差分擦除限 24px 内容带；一次性作业（非共享续画作业），单步多字安全。
- demo catch-up 预算 16→64（500Hz 下 missed 归零）。
- 实测：fps 20~23、帧 30ms 级、input 500＋/missed 0。

## 小数位跟随读数＋行2量程修复（2026-09-04，照片驱动）

- 行2量程恒 `--`：IDLE 快照时 `s_frame.trend_has_data` 恒假（刚 memset），误用它做有数判断。改判 `s_trend.has_sample`。
- 统计 1 位小数 vs 读数 4 位：新增 `main_display_format_stat_fixed()`（定长小数、补零不对齐截零、无 float printf），stage 按读数小数位重排三统计文本；Y 轴/量程保持轴刻度整数。
- 绿线槽位处缺口：依照片上线条完整，槽位重画不碰 y192；如仍见闪烁，多为槽位字形 1Hz 差分在可见页的毫秒级明暗泵，续观察。

## 换挡卡顿两实锤（2026-09-04 实测）

- MRWDP 逐槽回读探针常开：每槽 2 次切页＋慢读，500Hz 下单它就显著拖慢重建。默认关（`TREND_SWEEP_PROBE`，诊断才开）。
- 字形走慢速 Flash DMA（遗留 A/B 诊断 `DIRECT_DMA=1`，约 7ms/字）而非 SDRAM 缓存 BTE（约 1ms/字）。切回后稳态 fps 27~29（油门封顶 30.3）、帧百 ms 级、换挡只跌一窗即恢复。
- 另：此前照片（行2 `--`、统计 1 位小数）为旧版状态；量程修复＋小数位跟随已在 f513dfa，本次同板验证。

## 1Hz 卡顿主犯：PERF 串口打印（2026-09-04）

- `uart_put_byte` 逐字节忙等，~450B 的 PERF 行 @115200 ≈ 35~40ms，每秒一次正中显示流。另 header 秒帧/ADC/统计都在 1s 上，叠加更明显。
- 修复：计数保持 1s 窗，打印 5 分之一（`print_div`）；数值仍是最近 1s 窗的值。
- 其余 1Hz 项（header 秒帧＋ADC＋统计差分）单项几毫秒，保留。

## 空身份竞态（2026-09-04，轮换真凶）

- 轮换瞬间 buffer 刚清空、身份为空，背景照单全收全量重建并存下 `""`，下一帧身份一到又全量重建一次——双页 ×2 ≈ 2000 填充，5 秒冻屏。修：身份空且缓存非空时跳过本轮（~2ms 后身份即到），virgin 首建不受影响。
- 实测：轮换窗 fps 29~31 穿过（之前跌到 1~2），填充 2000＋→200，`behind≤2`。
- 真机换挡评估：同代码路径（单位变→invalidate→靶向重建＋渐进重扫），代价与 demo 轮换同量级；真机差异只会更小——手动换挡孤立事件（无 500Hz 持续 inc压力），且主机切换时读数常短暂停顿（catch-up 压力更低）。无主机在手无法全验证， host 测试清单：切 VDC→OHM→Hz 三档，每档看串口 `fps` 跌落深度（应≥20）与恢复窗数（应≤2 窗），目视趋势区无整幅闪白超过 1 帧。

## 换挡风暴定责与整页克隆（2026-09-05，diagnosing-bugs 全流程）

- 反馈回路：串口 PERF 5s 窗＋`[DBGrW]` 按窗 actor 聚焦（bg 步数/重启、INFO、live、增量/重扫槽数，事后清零）。
- 定责：`rest≈500` 系按提交聚合的口径误读（实为每合成一次的正常页切换）；按窗聚合后 bg/info/live/sweep 全正常，2084 填充＝两页整行文本重绘。`clone rc=01=TIMEOUT`：整页 BTE（~40ms）超出 `wait_bte_idle`（~10-20ms），改 8 分带后 `rc=00`。
- 修复：A 页 fresh 完成时整页 BTE 克隆→B 页＋行/趋势缓存镜像（读数缓存故意留旧，CLEAR 后全量 BTE 重画又快又对；BTE 失败回退原路）。重扫预算 16→32；排空期（behind>32）跳过 live（快照已新，无饿死）。
- 陈旧合成：TREND 入口比较 buffer 身份与帧单位（stem 对 stem，DC/AC 后缀要剥，否则 VDC 系永假变砖——已实锤一次零提交），失配则 abandon 回 IDLE。
- 开机 header-only 门控：首个完整读数合成前不提交纯顶行页。
- 实测：风暴 fps 1~5→2~23、fl 3300→1000~2300，稳态 fps 30、`missed=0`、测试与仿真全过。残留方差来自 demo 2s 状态风暴与轮换的相位重合。

## INFO 等轴（2026-09-05，Range 双值闪烁）

- 定责（`[DBGr]` 完成日志）：轮换后首遍 INFO（p=00）画 `AUTO --`（轴无效），随后 p=01、p=00 各画一次真值——管线里 INFO 跑在 TREND 轴重算之前，`--` 烤进像素和缓存。
- 修复：轴无效＋事务中时 INFO 延后一合成（行保持完整旧值），TREND 重算轴＋背景后，下合成画真值，同原子翻转。无数据轴仍诚实显示一次 `--`（背景必完成，事务必清除，无饿死）。左对齐本就固定，无需改。
- 实测：稳态 fps 30，同窗恢复。

## 二行固定格（2026-09-05，Range 推挤闪烁）

- 现象：换挡卡顿期 Range 值变宽推挤之后所有格子。渲染器弃用 `ui_layout_second_row`（结果全 void），自用 `bx` 游标流式排。
- 修复：格子焊死（Zin 162/108、Range 280/248、Rate 538/120，灯三槽 666/726/774，短分隔线 658），值区固定宽左对齐，分隔线在格边。只变字、不变位（趋势头三槽同 pattern）。徽标仍实测宽（函数切换罕见且原子）。
- 实测：稳态 fps 30~31；`verify.js` 全过。

## episode 跨度改按排空（2026-09-05，行闪后读数恢复）

- 现象顺序：读数先新→（闪烁期读数正常）→行闪烁更新→读数恢复。慢翻页把 1Hz/2s 抖动采样成可见闪烁。
- 改动：episode 跨度从定时 1500ms 改为 `transaction || behind>8`（排空 backlog 即剩余暴露面）；定时覆盖不了慢风暴。排空完自动解除，无饿死。
- 实测：稳态 fps 31，同窗恢复。

## 行快照（2026-09-05，三次闪：MANUAL空→MANUAL值→AUTO值）

- 根因：换挡值＋单位一条消息到，状态（AUTO/灯/速率）2s tick 姗姗来迟——模型单次换挡 stepping 三态，每态忠实绘制。
- 修复：episode 内行取快照（首个轴有效帧，8 串＋13 灯位）；读数＋趋势保持 live。安静（无事务＋behind≤8）自动解除；无数据轴永不快照。
- 实测：稳态 fps 31，同窗恢复。

## 删 episode 掩码（2026-09-05，档位名闪烁真凶）

- 根因：INFO-defer 让首合成不行 INFO，克隆把旧行像素＋旧缓存拷给 B；done 全局闩锁后 B 被掩码保护不让重画——A 新徽标/B 旧徽标来回切。
- 证明：任何“像素已正确才跳过”的掩码 ≡ 缓存命中检查本身；掩码要么 no-op，要么在缓存不一致时是毒药。整套 done/clone_ok 删除（-40 行），回到缓存命中 correctness。
- 诚实抖动（整秒时钟、2s 灯风暴在慢翻页下的单调更新）保留——时钟必须走，灯必须跟。
- 实测：稳态 fps 31，同窗恢复。

## 行 episode-done（2026-09-05，档位名闪烁＋变两次）

- 现象钉死（用户问答）：档位名闪烁、其余变两次，换挡期。慢合成必跨 2s 灯风暴/整秒跳变，A/B 各画一次。
- 修复升级：calm 值冻结改为 episode-done——一次换挡行最多画一次。`done_status/done_info` 在通过处闩锁；仅当克隆成功（像素有保证）才屏蔽；BTE 失败回退正常重画。跨度由 calm_until（fresh＋1500ms）界定，安静 IDLE 清除，无饿死。
- 实测：一次轮换零 dip 穿过；另一次风暴窗仍在（phasing 方差，A 侧刚性量＋2s 风暴重合），同窗恢复。

## 行 calm 窗（2026-09-05，稳定两次变化）

- 现象：换挡行必变两次（闪烁淡但看得出）。慢风暴合成（~1s/个）必跨整秒跳变：A 页行 uptime=X，B 页行 uptime=X+1。
- 修复：invalidate 快照 temp/uptime；fresh 完成后续 1500ms 为 calm 窗：帧画快照值、需求检查跳秒级项、dot 合成门控。灯/功能/量程仍实时（换挡内容必须更新）。窗口过自动恢复，无饿死。
- 实测：稳态 fps 30，轮换一窗 dip 同窗恢复。

## 拆除行冻结（2026-09-05，混血页回归）

- 现象：读数先变新→卡住→第二行闪烁更新→读数才恢复。冻结把行推迟到读数之后，人为制造混血页。
- 根因复盘：冻结当初是为防“行提前提交”，但 present 门控已保证同合成原子提交；冻结只剩代价。行在事务合成内照常画（隐藏页），同一次翻转。
- 改动：删 IDLE/STATUS 两处冻结＋非 baseline 脏位掩码，共三处回退。

## INFO 分隔线闪烁（2026-09-05，行决策日志定责）

- 现象：换挡卡顿期间顶二行两侧闪烁。`[DBGs]` 行决策日志显示节律正常（整秒 Sup 各页一次＋偶发 Irow），行绘制本身无病。
- 根因：INFO 在 y50 画 2px 分隔线，但 CLEAR 整阅读带（y50 起）每合成都擦掉——INFO 跑的合成有线、跳过的合成无线，横贯全幅闪烁。
- 修复：CLEAR 从 y52 起擦（`READING_Y + YELLOW_LINE_H`），分隔线存活；数字区 y64＋不受影响。插桩已清零。

## 开机事务误伤顶行（2026-09-05）

- 现象：开机顶两行缺席一会才出现（逐项问题已确认解决）。
- 根因：virgin 构建经 axis-expanded 走 invalidate→事务置起→IDLE 冻结 STATUS/INFO→首个提交页没有行，行等第二次提交。黑屏本来无可保护。
- 修复：`s_display_enabled` 为假时不启动事务（一行）。首个提交即带行；克隆同时让 B 页跳过 virgin 重建，开机更快。

## live 双页按调用 scoped（2026-09-05，双谱闪烁回归）

- 单页 live 的代价：live idx 全局、访问落交替合成，A 页画 slot0/2、B 页画 slot1，两页互补——翻页即双谱切换闪烁。
- 修复：双页只包 paint 调用（同 visit 内开、用完即关，不过夜）。两页每 visit 恒等（无闪烁）＋标记不泄漏到 STATUS/INFO/VALUE（无逐项）。sweep 两处保持 turn 内闭环。
- 教训：全局门按趟持有必泄漏、按页单写必互补——唯一安全粒度是按调用。

## live 双页标记泄漏（2026-09-05，用户目视定责）

- 现象钉死（用户问答）：行内徽标→Zin→Range→Rate→灯逐个出现（4 步＋，约 1s）；读数趋势正常；读数已是新档位。＝行像素直写可见页。
- 根因：`s_trend_sweep_drawing` 是全局双页门；live 一趟横跨多合成（预算 2/visit，换挡十几次访问），期间所有 STATUS/INFO/VALUE 都变双页直写。静态复查确认 sweep 两处都是 turn 内闭环，唯 live 是 pass 级泄漏。
- 修复：live 改隐藏页单页（删两处标记）；兄弟页经共享快照＋全局趟次单调收敛（同数字、差一帧，无闪烁）。sweep 重扫保持双页（示波器设计，趋势区用户已接受）。
- 实测：稳态 fps 31；轮换剩单页刚性量（一次性能窗，同窗恢复，`missed=0`）。

## 换挡原子提交（2026-09-05）

- 换挡背景分片本身在隐藏页完成，但每片结束仍可进入 `PRESENT`，导致顶部、Trend、纵轴按 `idx` 从左到右/从上到下被肉眼看到。
- 增加 `s_trend_rebuild_transaction`：单位/轴变化开始时置位，隐藏页完整背景（含绘图区、统计、纵轴）完成后清除；事务期间 `PRESENT` 退回趋势阶段继续续绘，旧可见页保持完整不变。
- 完成后只允许一次 page flip；普通同单位 live 刷新仍保持“一片即提交”，不重新引入读数冻结。
- 第二行 `INFO` 也必须被事务冻结；否则 `STATUS/INFO` 会在趋势重建前独立完成并提前提交，仍可见逐项重绘。换挡事务期间保留 dirty，待新趋势页翻转后再由普通帧处理。

## 轮换靶向重建（2026-09-04，周期分析驱动）

- 60s 串口周期分析：稳态 27~31fps（顶油门），低谷只在档位轮换窗（双页全量重建 ~600 填充＋重扫，fps 跌到 2）与 demo 2s 状态行（~200 填充）。
- 修复：`invalidate` 保留 unit 缓存；背景分 virgin 全建 / 轮换靶向（仅黑底＋header 内容条＋沟槽条＋统计＋Y 标签，徽标/线/纵线/任务栏不动）。
- 实测：稳态 fps 30，轮换同窗恢复；`missed=0`、无 error。

## 读数节拍抖动诊断（diagnosing-bugs 全流程，2026-09-04）

- 反馈回路：帧耗时直方图（<40/40–80/80–150/>150ms）＋慢帧 actor 位，30s 抓取确定性。
- 假设排序：H1 live 整槽无预算（单轮 230 填充≈66ms）＞ H2 header 秒帧 uptime 全重画（≈20ms）＞ H3 demo 2s 状态行（偶发）＞ H4 ADC（µs，排除）。
- `[DBG5]` 定责：`live=43~73, status=19~20`，其余个位数；BTE 拷贝 `copy=3~4ms` 无罪。
- 修复：差分 4 字形预算（跨轮续跑）＋uptime 等长差分（temp 变回全量）＋live 单页画＋header 条带 BTE 同步；10Hz 摊薄（同量分散，峰值 15→5ms）。
- 回归：无 host 接缝（渲染器需硬件），以串口回路为准：fps 29~32、帧 ~10ms、gap<40、统计 10Hz 跟随、`missed=0`。插桩清零已验证。
- 教训：高频输入下"摊薄"不减少总量，只在总量小时有效；总量大时靠预算＋差分降总量。

## 刷新摊薄 1Hz→10Hz（2026-09-04）
