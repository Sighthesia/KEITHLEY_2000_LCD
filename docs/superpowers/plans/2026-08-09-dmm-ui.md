# K2000 DMM UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 STM32F103C8T6 + LT7680A-R 上实现现代台式万用表 UI。增强型替换——保留 K2000 主机语义（主机权威、按键透传），TFT 提供趋势/统计等增强。**里程碑-1 = 读数页**（大读数 + 单位 + 状态指示器 + 特殊读数 + 键盘透传）；趋势/统计为后续独立场景。

**Architecture:** 多场景框架。**所有视图在逻辑 960×320 横屏空间编写**；物理面板方向（当前竖放 320×960，未来横放 960×320）隔离为**帧缓冲变换适配器**（当前=纯转置 `fb_x=uy; fb_y=ux`，ADR-0001）。独立全屏场景（读数/趋势/统计），里程碑-1 只装读数场景，DISPLAY/TREND 本地键暂不解释（ADR-0002）。逻辑组件(`k2000_proto`/`ui_model`/`reading_split`/`trend_buf`/`status_bar`/`keypad`)为纯 C、双工程同步，host gcc 在 PC 单测；硬件组件(`hal_board` SPI1/UART/键盘、`lt7680_gfx` 几何原语、各 view 渲染)走真机验收。

**Tech Stack:** STM32F103C8T6 (ARM Cortex-M3), STM32Cube HAL, LT7680A-R (SPI 控制 + 18-bit RGB), arm-none-eabi-gcc, host gcc (PC 单测), Python 3 + Pillow (字库生成), CMake/Ninja (CubeMX 工程), Makefile (firmware 骨架)。

## Global Constraints

- 目标 MCU:`STM32F103C8T6`,64KB Flash / 20KB RAM(链接脚本 `STM32F103xx_FLASH.ld`:RAM ORIGIN 0x20000000 LENGTH 20K)。
- 时钟:当前 HSI 8MHz、PLL 关闭、SYSCLK=HCLK=PCLK1=PCLK2=8MHz(不改动 SystemClock_Config)。
- 两个工程必须同步:`firmware/src/*` 与 `KEITHLEY_2000_LCD/Core/Src/*`、`Inc/*` 同名文件内容一致。改逻辑组件必须同步两份,两处构建都要过。
- firmware 骨架编译:`make -C firmware`,flags `-mcpu=cortex-m3 -mthumb -std=gnu11 -Os -Wall -Wextra -Werror -ffreestanding`。
- CubeMX 工程构建:`cmake --build KEITHLEY_2000_LCD/build/Release --target KEITHLEY_2000_LCD.elf`(生成的 `.elf` 在 `KEITHLEY_2000_LCD/build/Release/KEITHLEY_2000_LCD.elf`,用这个路径烧录;顶层 `build/` 是历史残留,勿烧)。
- 零告警(-Werror)。不得引入 C99 之后的新特性(gnu11)。
- **视图坐标 (ADR-0001)**: 所有视图逻辑坐标上限 960×320;物理方向经帧缓冲变换适配器映射到 LT7680 原生 320×960 帧缓冲(当前=转置 `fb_x=uy; fb_y=ux`)。适配器是唯一懂物理方向的地方;未来物理横放只改适配器,视图零改动。
- **场景模型 (ADR-0002)**: 独立全屏场景,`scene_enter/exit/render` 接口;里程碑-1 只装读数场景;DISPLAY/TREND 本地键暂不解释(无目标场景),仍透传主机。
- 协议事实:`0x0D` 是消息起始/同步符;`0x04`=POS;`0x0B`=blink(参数 0x01 开始/0x00 结束);状态 TAG `0x06`(REM/TALK/LSTN/SRQ)、`0x07`(SHIFT/TIMER/MATH/REAR/diode/beep/4W/⇅)、`0x08`(HOLD/TRIG/FAST/MED/SLOW)、`0x09`(REL/FILT/AUTO/ERR/*/BUFFER/STAT)、`0x0A`(STEP/SCAN/CH1/CH2)、`0x0E`(CH3-CH10);每 TAG 的 bit 位映射 `0x80`=bit7 对应第一个指示符。
- **状态指示器(里程碑-1 核心子集)**: 只渲染 HOLD / REM / REL / TRIG / AUTO / ERR;其余位保留在状态模型但不显示。全量 bit→标签映射来自 ODS RX 表,位序(bit7=首标签)已由代码注释确认。
- 键盘矩阵:列=PB0..PB7(输出),行=PC13/PC14/PC15/PB10(输入上拉)。键码 `0x41`(SHIFT)..`0x60`(EXIT),`0x40`=all released。**里程碑-1 全量透传主机**;DISPLAY/TREND 键码预留,不本地解释。矩阵映射(ODS TX 表)在 Task 11 真机逐格核对。
- 大数字字库:JetBrains Mono 48×96,字符集 `"0123456789.+-Ee%mukKMWVOhDAC"`(28 字符,已验证),1bpp,存 STM32 Flash。
- 小号文本字体(里程碑-1 新增):**12×24**,覆盖 ASCII + `µΩ°±`,1bpp,同时用于状态栏与单位行(与 48×96 大数字成 1:2)。**里程碑-1 无中文**,`font_cn` 留到确有中文标签需求时再建。
- 读数拆分:`reading_split` 数字区(含 `+ - . E e`)→ value,尾部字母/符号 → unit(可为空);`OVERFLOW` → 红字、`----` → 灰字,均不压 trend_buf。单位字符缺字形回退 `?`;不做 `u→µ` 之类字符替换(协议未证实送 µ 字节)。
- 光标:`POS` 是 value 字符串内从左第 0 个字符起的索引(钳位到串长);大读数下方画闪烁下划线;闪烁翻转用本地 tick,不经主机。
- 功能区只显示**单位串**(量程信息蕴含其中);功能/量程不虚构,待协议逆向到可靠字段再补。
- 刷新:变化触发区域重绘;大数字字形 blit(非逐像素 set_pixel);无全页 GE clear(场景切换除外)。
- 采样触发(趋势里程碑):值变化必采样;值相同则距上次 ≥250ms 必采样。量级突变 >10× 清空缓冲。
- 特殊读数:`OVERFLOW` → 红字;`----` → 灰字;均不压入 trend_buf。
- 键盘发送:按下发键码、释放发 `0x40`,20ms 防抖,主循环轮询。
- 烧录:`openocd -f openocd.cfg -c "init" -c "halt" -c "program ...elf verify" -c "reset" -c "shutdown"`(`reset_config none`,不要 `program ... reset exit`);复位报错时手动按复位键。
- 不要在本计划中提交任何未在任务中明确列出 commit 的更改。
