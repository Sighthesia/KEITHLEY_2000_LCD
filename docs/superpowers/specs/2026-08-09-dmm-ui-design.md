# K2000 TFT 万用表 UI 设计

日期:2026-08-09
状态:已批准(设计评审通过)

## 背景与目标

KEITHLEY 2000 VFD 替换板(STM32F103C8T6 + LT7680A-R + ST7701S 320×960 面板 + W25Q128JV)已通过彩条里程碑。本设计定义自绘台式万用表 UI:模仿现代台式万用表(KEITHLEY DMM6500 / Keysight 34465A),区别于原版 VFD 分段复刻。

## 核心决策

| 决策点 | 结论 |
|---|---|
| UI 定位 | 现代台式万用表风格(DMM6500/34465A),非 VFD 复刻 |
| 屏幕方向 | 横放 960×320(需处理旋转,验证点在 P1) |
| 趋势图数据源 | 从现有协议(TAG+value)读数流截获,环形缓冲 |
| 交互深度 | 最小可用:单场景常驻,键盘默认透传主机 |
| 语言 | 中文界面(GB2312 库含 ASCII 半角,可混排英文单位);固定中文,运行时 lang 标志接口预留 |
| 读数格式 | 7 位大数字,JetBrains Mono 大号点阵 |
| 状态指示符 | 保留(REM/HOLD/REL/AUTO/TRIG/ERR/BUFFER/STEP/SCAN/CH1-10),顶部状态栏现代呈现 |
| 趋势图位置 | 底部(宽 960,可画更长历史),常驻 |
| 方案 | 混合:大数字自绘入 STM32 Flash + 中文 GB2312 入 W25Q128 官方字库通道 + 趋势图 draw_line/BTE |

## 屏幕布局(960×320 横放,单场景常驻)

```
┌────────────────────────────────────────────────┐
│ 状态栏: REM HOLD REL FILT AUTO TRIG ERR ...CH1 │  ← ~24px,图标+文字
├────────────────────────────────────────────────┤
│                      1.234567                   │  ← 7位大数字 (JetBrains Mono 48×96)
│                       V DC                      │  ← 单位/功能 (中文字库通道)

│                      趋势图                       │  ← ~120px 高, 960 宽
│  ┌─网格+坐标轴一次画好──────────────────────┐     │
│  │  增量 draw_line + 满屏 BTE 左移          │     │
│  └─────────────────────────────────────────┘     │
└────────────────────────────────────────────────┘
```

### 组件清单

1. **`lt7680_gfx` 扩展**(已有):新增 `draw_line`/`draw_polyline`、`draw_circle`、BTE 水平左移、SPI-flash 字库通道封装。现有 fill_rect/set_pixel 不动。
2. **`font_digits` 新增**:JetBrains Mono 光栅化 C 数组(48×96,`0-9 + - . E` + µΩkMVA 等 ≈40 字符 ≈12KB,存 STM32 Flash),`font_digit_bitmap(c)`。
3. **`trend_buf` 新增**:环形缓冲(MCU RAM,~1000 采样,每采样存值+时间戳;窗口级 min/max 由 trend_view 扫描维护)。
4. **`trend_view` 新增**:网格坐标一次画好,新点增量画线,满屏 BTE 左移一列。
5. **`main_display` 新增**:大数字 + 单位/次级文本渲染(单场景,无场景切换)。
6. **`status_bar` 新增**:顶部指示符现代呈现。
7. **`keypad` 新增**:PB0..PB7 × PC13/14/15/PB10 矩阵,键码 0x41..0x60。默认按原协议 TX 表编码透传主机(主机是控制方);本地导航键消费暂缓。

### 旋转处理

横放 960×320,`hal_panel_init()` 阶段配置 ST7701S 扫描方向 + LT7680 内存方向(实现时按 DS 核对,独立验证点;备选 ST7701S MADCTL)。

## 数据流与刷新策略

### 数据流

```
UART(主机) → k2000_proto 解析
   ├─ 读数 TAG → ui_model.value  → main_display 大数字刷新
   │            └─ 同时压入 trend_buf (环形缓冲)
   ├─ 状态 TAG(0x06-0x0E)→ ui_model 指示符 → status_bar 点亮/熄灭
   ├─ POS/光标/闪烁 → ui_model → main_display
   └─ 未知字节 → 忽略(不阻塞)

键盘矩阵 → keypad → 键码(0x41-0x60) → UART 发给主机
```

### 刷新策略

| 元素 | 策略 | 原因 |
|---|---|---|
| 大数字 | 仅在读数变化时重绘该字符 | 读数 ~0.5-5Hz,全量重绘毫秒级 |
| 状态栏 | 指示符状态变化时增量点亮/熄灭 | 低频事件 |
| 趋势网格/坐标 | 启动时画一次,永久保留 | 不变元素 |
| 趋势新点 | 新采样 → `draw_line(prev, new)` 一条线 | LT7680 几何引擎自己光栅化 |
| 趋势满屏 | 全部样本 BTE 左移一列 + 画新列 | 单条 BTE 命令,~ms 级 |
| 背景 | 初始 fill_rect 一次 | — |

### 性能估算

- `draw_line`:MCU 发送 ~10-20 字节命令 → 微秒级
- BTE 左移一列(960×120):LT7680 内部 SDRAM 间操作 ~几百 µs
- 大数字重绘(48×96 × 7 字符 ≈ 32K 像素逐写):每字符 ~5-10ms,5Hz 读数时可接受;预留 `lt7680_gfx_bitblt()` 接口,实测超 15ms 再启用 BTE/DMA 提速
- 结论:趋势图滚动无性能问题;唯一优化点是大数字位图写入

### 错误处理

- `lt7680_gfx` 调用失败:记录到 UART 调试口,UI 继续运行(不阻塞)
- `trend_buf` 溢出:环形覆盖(趋势图天然丢弃最旧点)
- 未知协议字节:丢弃,不影响状态机
- 字库未烧录(W25Q128 空):中文区域显示 `?` 回退,数字区不受影响

## 字库方案与 Flash 布局

### 双通道

| 通道 | 内容 | 存放 | 渲染方式 |
|---|---|---|---|
| 数字通道 | JetBrains Mono 48×96 点阵(`0-9 + - . E` 等 ≈40 字符) | STM32 Flash C 数组 ≈12KB | MCU 读数组 → 直写 SDRAM |
| 中文通道 | GB2312 16×16 全库 | W25Q128 bin ~256KB | LT7680 字库通道 `Print_String` |
| 符号补充 | ° Δ 等少量符号 | 并入数字通道 C 数组 | MCU 直写 |

### 生成工具(Python,新增 `tools/`)

1. `tools/make_digit_font.py` — Pillow 加载 JetBrains Mono TTF → 光栅化 48×96 → `font_digits.c/h`(1bpp)
2. `tools/make_gb2312_bin.py` — 生成 GB2312 16×16 点阵 bin(开源点阵数据或 Pillow 渲染)

### W25Q128 Flash 布局

```
0x000000  LT7680 bootloader(官方工具要求)  ← 若用官方字库通道需保留
0x00xxxx  GB2312 16×16 字库 bin  (~256KB)
0x05xxxx  (预留)图标/开机画面
```

> W25Q128 挂 LT7680 SPI-master,不经 STM32;烧录方式 = LT_IMAGE_TOOL 或专用 SPI 编程器(非 STM32 SWD)。

### 语言

最小可用阶段固定中文,运行时 lang 标志接口预留,不做切换界面。

## 实现计划(分阶段,每阶段独立验收)

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| P1 | LT7680 横放旋转 + `draw_line`/`draw_circle` 几何原语 | 屏幕上画线/圆可见;现有彩条不回归 |
| P2 | `tools/make_digit_font.py` + `font_digits.c` + 大数字渲染 | 数字位图正确;测试图样显示 "1234567" |
| P3 | `trend_buf` 环形缓冲 + `trend_view` 网格/坐标/增量画线 + BTE 左移 | 注入伪数据(如正弦),趋势图连续滚动正确 |
| P4 | `status_bar` + 协议状态 TAG 消费 | 串口发 REM/HOLD/AUTO 等,状态栏对应点亮 |
| P5 | GB2312 字库 bin 生成 + 中文通道接通 | 中文标签/单位显示正确;字库缺失时回退 `?` |
| P6 | `keypad` 矩阵扫描 + 键码 TX 编码回主机 | 按键 → UART 发对应 0x41-0x60 字节 |
| P7 | 整合:真机读数驱动全 UI | 接主机串口,读数/状态/趋势图联动正确 |

## 测试策略

- 离线构建(每阶段):`cmake --build KEITHLEY_2000_LCD/build/Release` + `firmware/ make` 双工程同步,零告警
- PC 侧验证:`trend_buf`/协议解析等纯逻辑在 PC 编译单测(无硬件依赖,`firmware/` 骨架已有此模式)
- 真机验证:逐阶段烧录,串口 115200 打印 `STATUS`/调试;固定注入序列(正弦波/阶跃)验证趋势图
- 回归:每阶段保留彩条自检入口(`LT7680_SPI_SELFTEST`),确认改动不破坏既有显示

## 风险与对策

| 风险 | 对策 |
|---|---|
| 48×96 逐像素写太慢 | P2 实测,预留 BTE 优化接口 `lt7680_gfx_bitblt()` |
| LT7680 字库通道寄存器细节(RA8876 vs LT7680 差异) | P5 先小字符集验证,参考 lt7680-st7701 skill 已核对寄存器 |
| 横放旋转寄存器不确定 | P1 首项即验证,备选 ST7701S MADCTL |
| 64KB Flash 容量吃紧 | 数字数组 1bpp 压缩;必要时裁掉不常用符号 |
