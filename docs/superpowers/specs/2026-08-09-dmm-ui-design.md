# K2000 TFT 万用表 UI 设计

日期:2026-08-09
状态:已批准(设计评审通过;2026-08-09 grilling 会话增补 P0 前置与趋势图/读数细节)

## 背景与目标

KEITHLEY 2000 VFD 替换板(STM32F103C8T6 + LT7680A-R + ST7701S 320×960 面板 + W25Q128JV)已通过彩条里程碑。本设计定义自绘台式万用表 UI:模仿现代台式万用表(KEITHLEY DMM6500 / Keysight 34465A),区别于原版 VFD 分段复刻。

## 核心决策

| 决策点 | 结论 |
|---|---|
| UI 定位 | 现代台式万用表风格(DMM6500/34465A),非 VFD 复刻 |
| 屏幕方向 | 横放 960×320(需处理旋转,验证点在 P1) |
| 趋势图数据源 | 从现有协议(TAG+value)读数流截获,环形缓冲 |
| 交互深度 | 最小可用:单场景常驻,键盘默认透传主机 |
| 语言 | 中文界面:静态标签中文子集点阵入 STM32 Flash;协议本身是纯 ASCII(主机不发送中文),本轮不碰 W25Q128 官方字库通道 |
| 读数格式 | 7 位大数字,JetBrains Mono 大号点阵,有效数字自适应 |
| 状态指示符 | 保留(REM/HOLD/REL/AUTO/TRIG/ERR/BUFFER/STEP/SCAN/CH1-10),顶部状态栏现代呈现,只显示活跃项 |
| 趋势图位置 | 底部(宽 960,可画更长历史),常驻 |
| 方案 | 混合:大数字自绘入 STM32 Flash + 中文子集入 STM32 Flash(非 W25Q128)+ 趋势图 draw_line/BTE |

## P0 前置(grilling 增补,先于 P1 实施)

设计评审发现三项**事实级硬伤**,必须在任何 UI 工作前修复:

| # | 问题 | 事实来源 | 修复 |
|---|---|---|---|
| P0-1 | **SPI 是软件 GPIO 位翻转**,非硬件 SPI;HSI 8MHz 下约 80-130 kbit/s。7 位大数字全量刷新 ~64KB ≈ 60s,单字符 ~8s,UI 不可行 | hal_board.c:57-71,main.c:224-240 | 启用 SPI1 硬件外设(PA4/5/6/7 即 SPI1_NSS/SCK/MISO/MOSI 复用),HSI 8MHz 下 PCLK2=8MHz → SPI1 最高 2MHz,约 25-30× 提速;验证点 P1 |
| P0-2 | **UART BRR 公式 16 倍错误**:`BRR = PCLK2*16/BAUD` 应为 `PCLK2/BAUD`;8MHz 下实际 ~7.2k 而非 115200,与验收记录矛盾 | hal_board.c:163 | 改公式 `BRR = PCLK2/BAUD`,P0 加真机 loopback/示波器实测波特率验收项 |
| P0-3 | **解析器不识别状态 TAG**:VALUE 态只把 `>=0x80` 当新 tag,状态 TAG 0x06-0x0E(<0x80)混在读数消息中会被吞进 value;POS 解析恒 0(`evt.pos` 无赋值) | k2000_proto.c:85-87,63;ODS RX R4-R10 | 扩展 VALUE 态:白名单识别 0x06-0x0E → emit `K2000_EVT_STATUS`;修复 POS:0x04 后数字字节写入 `evt.pos` 而非 value |

P0-1/P0-2 改动 hal_board.c;P0-3 改动 k2000_proto.c/h(两工程同步)。三项均须通过既有彩条回归(`LT7680_SPI_SELFTEST`)确认不破坏现状。

### 组件清单

1. **`lt7680_gfx` 扩展**(已有):新增 `draw_line`/`draw_polyline`、`draw_circle`、BTE 水平左移、bitblt 接口(`lt7680_gfx_bitblt`,P2 后按实测决定是否启用)。现有 fill_rect/set_pixel 不动。
2. **`font_digits` 新增**:JetBrains Mono 光栅化 C 数组(48×96,`0-9 + - . E` + µΩkMVA 等 ≈40 字符 ≈12KB,存 STM32 Flash),`font_digit_bitmap(c)`。
3. **`font_cn` 新增**:静态中文子集点阵(仅"趋势图"等几个标签 ≈10-20 汉字 × 16×16 ≈ 640B-1.3KB,存 STM32 Flash),与数字同一渲染路径。
4. **`trend_buf` 新增**:环形缓冲 512 点,每采样 `float` 值 + `uint32` 时间戳(HAL tick)≈4KB RAM。
5. **`trend_view` 新增**:网格坐标一次画好,新点增量画线,满屏 BTE 左移 2 列;Y 轴自动量程 ±10% 边距,右上角 min/max 数值标签。
6. **`main_display` 新增**:大数字(有效数字自适应,右侧对齐)+ 单位/功能行 + MIN/MAX/AVG 次级行(窗口统计)。
7. **`status_bar` 新增**:顶部指示符,只显示活跃项。
8. **`keypad` 新增**:PB0..PB7 × PC13/14/15/PB10 矩阵,主循环轮询 + 20ms 防抖,键码 0x41..0x60;按下发键码、释放发 0x40(all released)透传主机。

### 旋转处理

横放 960×320。首选 ST7701S MADCTL:在 `hal_panel_init()` page_00 序列 0x11 附近发 `0x36=0x60`(备选 0xE0 反向),同时把 LT7680 面板时序换成 960×320(main.c `PANEL_LANDSCAPE` 宏)。MADCTL 值、RGB 接口下是否生效、PCLK 是否需重调均为真机验证点;若 MADCTL 无效,回退为 LT7680 内存方向(MACR REG[02h] bit[2:1])。

## 数据流与刷新策略

### 数据流

```
UART(主机) → k2000_proto 解析
   ├─ 读数消息 → 拆分数字串+单位串 → ui_model.value/unit → main_display
   │            └─ 数字串 → trend_buf (触发条件见 Q17)
   ├─ 状态 TAG(0x06-0x0E)→ K2000_EVT_STATUS → ui_model 指示符 → status_bar
   ├─ POS/光标/闪烁 → ui_model → main_display
   └─ 未知字节 → 忽略(不阻塞)

键盘矩阵 → keypad(轮询+防抖) → 键码/释放码 → UART 发给主机
```

### 读数拆分(P0-3 + Q11)

读数消息 = `0x0D + ASCII串`。解析器在 field 完整后,对 `field.value` 做数字/字母切分:数字部分(含 `+ - . E e`)→ `value`,后续字母/符号部分 → `unit`。特殊值判定:value 为 `OVERFLOW` → 红字显示;`----` → 灰字显示,均不作数字解析,不压入 trend_buf。

### 趋势图采样与缩放(Q14-Q18)

| 项 | 决策 |
|---|---|
| 缓冲 | 512 点,`float` 值 + `uint32` 时间戳 ≈4KB RAM |
| 触发 | 值变化必采样;值相同则距上次采样 ≥250ms 必采样(Q17) |
| X 轴 | 按采样点(1px=2 点/2px 分辨率),X 标签显示 MM:SS 相对时间戳 |
| Y 轴 | 自动量程:窗口 min/max ±10% 边距;右上角 min/max 数值标签 |
| 窗口 | 480 点可视(2px/点),满屏 BTE 左移 2 列 |
| 清空 | 读数量级突变 >10× 时清空缓冲并重画(Q18) |

### 刷新策略

| 元素 | 策略 | 原因 |
|---|---|---|
| 大数字 | 仅在读数变化时重绘该字符 | 读数 ~0.5-5Hz,全量重绘毫秒级 |
| 状态栏 | 指示符状态变化时增量点亮/熄灭 | 低频事件 |
| 趋势网格/坐标 | 启动时画一次,永久保留 | 不变元素 |
| 趋势新点 | 新采样 → `draw_line(prev, new)` 一条线 | LT7680 几何引擎自己光栅化 |
| 趋势满屏 | 全部样本 BTE 左移 2 列 + 画新列 | 单条 BTE 命令,~ms 级 |
| 背景 | 初始 fill_rect 一次 | — |

### 性能估算(P0-1 后,SPI1 @2MHz)

- SPI1 @2MHz ≈ 250KB/s。大数字单字符 48×96×2B = 9.2KB → ~37ms;7 字符全量 ~256ms。仅重绘变化字符时读数刷新可接受(读数 ~0.5-5Hz)。若实测超标,启用 `lt7680_gfx_bitblt()`/BTE 从 Flash 搬图。
- 趋势图:draw_line 微秒级;BTE 左移 2 列(960×120)LT7680 内部 SDRAM 操作 ~几百 µs,无性能问题。

### 错误处理

- `lt7680_gfx` 调用失败:记录到 UART 调试口,UI 继续运行(不阻塞)
- `trend_buf` 溢出:环形覆盖(趋势图天然丢弃最旧点)
- 未知协议字节:丢弃,不影响状态机
- 中文子集字库缺失:显示 `?` 回退,数字区不受影响(本轮字库为静态数组,不存在"未烧录"场景)

## 字库方案与 Flash 布局

### 通道(grilling Q9 修订)

| 通道 | 内容 | 存放 | 渲染方式 |
|---|---|---|---|
| 数字通道 | JetBrains Mono 48×96 点阵(`0-9 + - . E` 等 ≈40 字符) | STM32 Flash C 数组 ≈12KB | MCU 读数组 → 直写 SDRAM |
| 中文通道 | 静态中文标签子集 16×16(仅 UI 固定标签 ≈10-20 汉字) | STM32 Flash C 数组 ≈1.3KB | MCU 直写(与数字同路径) |
| 符号补充 | ° Δ 等少量符号 | 并入数字通道 C 数组 | MCU 直写 |

> **本轮不使用 W25Q128**。官方字库通道(GB2312 全库)依赖 LT_IMAGE_TOOL、字库须从 Flash 0x0000 起始、烧录非 SWD、且 LT7680 字库通道寄存器未经验证,风险过高;协议本身是 ASCII,无任意中文内容需求。留作未来扩展(可选 P8)。

### 生成工具(Python,新增 `tools/`)

1. `tools/make_digit_font.py` — Pillow 加载 JetBrains Mono TTF → 光栅化 48×96 → `font_digits.c/h`(1bpp)
2. `tools/make_cn_font.py` — 生成中文静态标签子集 16×16 点阵 → `font_cn.c/h`(1bpp)

### 语言

协议纯 ASCII;中文只出现在面板静态标签。固定中文界面,运行时 lang 标志接口预留(本轮不实现切换)。

## 实现计划(分阶段,每阶段独立验收)

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **P0** | SPI1 硬件化;UART BRR 修复 + 真机实测;解析器扩展状态 TAG + POS 修复 | SPI 提速 ~25×;UART loopback 实测 115200;串口发状态字节,解析器 emit `K2000_EVT_STATUS`;彩条回归通过 |

| P3 | `trend_buf` 环形缓冲 + `trend_view` 网格/坐标/增量画线 + BTE 左移 + 自动量程 | 注入伪数据(如正弦),趋势图连续滚动正确,min/max 标签更新 |

## 测试策略

## 风险与对策

| 风险 | 对策 |
|---|---|
| SPI1 @2MHz 下大数字逐写仍慢 | P2 实测,预留 BTE 优化接口 `lt7680_gfx_bitblt()` |
| LT7680 字库通道寄存器细节(RA8876 vs LT7680 差异) | 本轮不使用字库通道(Q9 已规避);P5 中文走自绘子集 |
| 横放旋转寄存器不确定 | P1 首选 ST7701S MADCTL(0x36,真机验证 0x60/0xE0),备选 LT7680 MACR REG[02h] |
| 64KB Flash 容量吃紧 | 数字数组 1bpp 压缩;中文子集仅固定标签 |
| P0-3 解析器改动影响既有协议 | P0 验收含彩条回归 + 协议单测 |
| UART 波特率与主机不匹配 | P0 真机 loopback/示波器实测确认 |
