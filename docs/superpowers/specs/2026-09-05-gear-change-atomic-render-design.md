# 换挡原子显示事务与有界渲染设计

## 目标

换挡和启动时，功能名称、顶部徽标、Range、Rate 及状态灯只能以完整状态一次提交；读数仍保持实时更新。趋势单位/坐标轴重建和双页同步必须分片执行，不能阻塞读数提交或造成可见的逐段重绘。

## 当前问题

协议事件不是原子到达的：读数与单位先到，AUTO、Rate、灯状态可能随后到达。当前渲染器按中间模型状态启动 STATUS/INFO 阶段，因此同一次换挡可能依次显示空白状态、旧状态和新状态。换挡还会触发趋势背景、轴和兄弟页克隆，造成长时间提交间隔。

## 设计

### 1. 原子行快照

- 读数事件启动换挡事务，并标记待提交的行状态。
- 事务期间，模型和读数继续接收更新，但 STATUS/INFO 使用上一份已提交行快照；若是启动阶段没有上一份快照，则保持隐藏，不向可见页提交半成品。
- 事务完成条件必须是已有读数、单位身份与趋势轴身份一致，并且本轮协议状态已经经过一个完整的稳定窗口。稳定窗口采用现有调度时钟和事件代次，不使用固定长延时。
- 完成时一次生成完整行快照，包含功能名称、顶部徽标、Range、Rate、阻抗、温度、时间和状态灯。快照只在隐藏页绘制，随后同步到另一页缓存。
- 快照提交后，事务状态清除；后续正常变化按字段差分绘制。触发点闪烁仍可单独更新，不得使整行重新绘制。

### 2. 启动首帧

- 首帧在显示打开前完成完整状态快照和所有行绘制。
- 显示打开前不得提交只含读数、只含徽标或只含状态行的中间页。
- 无协议数据时显示既有 `NO DATA`/空状态，不伪造功能名称或 Rate。

### 3. 有界换挡渲染

- 每次主循环只允许执行一个固定数量的 glyph、trend column 或 clone band 工作单元。
- 趋势背景、轴标签和兄弟页同步继续使用可恢复游标；任何阶段未完成都不能触发可见页翻转。
- 读数绘制使用独立预算。即使趋势重建未完成，只要读数和行快照已经完整，仍可提交隐藏页。
- 禁止换挡路径调用等待整个趋势事务完成的阻塞式 present。
- 切换单位时保留上一档可见趋势，直到新档完整背景准备好；新档的读数与行不得提前显示在旧档趋势上。

## 数据流

1. 协议事件更新模型并递增读数代次。
2. 渲染器在隐藏页构建实时读数。
3. 若处于换挡事务，行使用上一份快照；若快照尚未存在，则保持旧行或在启动时保持黑屏。
4. 趋势后台按预算推进，完成后确认单位/轴身份一致。
5. 生成新行快照并绘制 STATUS/INFO。
6. 完整隐藏页原子翻转；另一页只复制已完成区域和缓存元数据。

## 验收

- 换挡时功能名称、顶部徽标、Range、Rate 和状态灯不出现空白、中间状态或重复闪烁。
- 启动时功能名称最多一次从隐藏状态切换为完整状态，不出现三次重绘。
- 换挡期间读数不冻结；连续 30 秒采样中 `missed=0`，稳态 `fps` 维持约 30。
- 任意趋势后台分片都不会让可见页出现半条轴、半个徽标或新旧档位混合。
- 现有 `node sim/verify.js`、宿主测试和 CubeMX Release 构建全部通过。

## 不在范围内

- 不改变 K2000 协议字段含义、面板布局常量、字体资源或趋势坐标定义。
- 不通过增加固定延时掩盖事件不同步问题。
